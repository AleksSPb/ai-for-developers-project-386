# Соглашение о сообщениях коммитов

Проект следует [Conventional Commits 1.0.0](https://conventionalcommits.org/en/v1.0.0/).
Соблюдение правил проверяет `commitlint` — сообщение не пройдёт мимо хука `commit-msg`.

## Формат

```
<type>(<scope>): <описание>

[тело]

[footer]
```

```text
feat(vite-project): добавить создание звонка

Звонок нельзя было отменить после начала: пользователь звонил и не мог
передумать. Отмена доступна только до начала.

Refs: #14
```

## Язык

| Часть | Язык | Почему |
|---|---|---|
| `type`, `scope` | латиница | их разбирают автоматические инструменты |
| описание, тело | русский | README и общение с наставником на русском |

## Типы

Допустимы только эти 11 значений — список задан конфигом и проверяется:

| Тип | Когда применять |
|---|---|
| `feat` | новая пользовательская возможность |
| `fix` | исправление бага |
| `test` | тесты и тестовая инфраструктура |
| `chore` | зависимости, конфиги, обвязка — то, что пользователь не видит |
| `docs` | README и документация |
| `refactor` | перестройка кода без изменения поведения |
| `style` | только форматирование, без логики |
| `perf` | ускорение |
| `ci` | GitHub Actions и прочий CI |
| `build` | система сборки и зависимости сборщика |
| `revert` | откат ранее сделанного коммита |

Только `feat` и `fix` имеют смысл для SemVer: `feat` → минорный релиз, `fix` → патч.

## Область (scope)

Указание области необязательно по спецификации, но в этом проекте принято писать
область того модуля, который меняется: `vite-project` или `server`. В корне
репозитория нет ни `package.json`, ни `pom.xml`, поэтому область соответствует
папке, а не чему-то ещё. Правки корневых файлов (`README.md`, `AGENTS.md`,
`docs/`) идут без области.

## Описание

- с маленькой буквы — `subject-case` запрещает `Start case` (`Start-case`)
- без точки в конце — `subject-full-stop`
- не длиннее 100 символов **вместе с префиксом** — `header-max-length`
- краткое и в отглагольном виде: «добавить», «исправить», «вынести», а не «добавил»

## Тело

Отделяется от описания одной пустой строкой — `body-leading-blank`.
Не длиннее 100 символов в строке — `body-max-line-length`.

Тело отвечает на вопрос **почему** так сделано, а не как: объяснение выбора
остаётся в диффе, а мотив — нет. Хорошее тело отвечает на «а почему нельзя было
проще?».

## Footer

Отделяется от тела одной пустой строкой — `footer-leading-blank`.
Токен пишется через дефис и разделяется двоеточием или пробелом с решёткой:

```text
Refs: #14
Reviewed-by: @onator
```

Исключение из правила о дефисе — `BREAKING CHANGE`, где пробел в токене
разрешён спецификацией.

## Ломающие изменения

Помечаются либо `!` перед двоеточием, либо футером:

```text
feat(api)!: принимать дату звонка в ISO 8601

BREAKING CHANGE: принимали Unix-таймстемпы, теперь ждём дату в ISO 8601.
```

Допустимы оба способа; если `!` уже стоит в префиксе, `BREAKING CHANGE:`
в футере можно опустить.

## Откат

Тип `revert` плюс ссылки на откатываемые коммиты:

```text
revert: вернуть кнопку отмены звонка

Refs: 676104e, a215868
```

## Что именно проверяет commitlint

Уровни: `2` — ошибка, коммит не пройдёт; `1` — предупреждение.

| Правило | Уровень | Значение |
|---|---|---|
| `type-enum` | 2 | тип из списка выше |
| `type-empty` | 2 | тип обязателен |
| `type-case` | 2 | тип в нижнем регистре |
| `subject-empty` | 2 | описание обязательно |
| `subject-case` | 2 | не `Start case` |
| `subject-full-stop` | 2 | нет точки в конце описания |
| `header-max-length` | 2 | не длиннее 100 символов |
| `header-trim` | 2 | без пробелов по краям |
| `body-max-line-length` | 2 | не длиннее 100 символов в строке |
| `footer-max-line-length` | 2 | не длиннее 100 символов в строке |
| `body-leading-blank` | 1 | пустая строка перед телом |
| `footer-leading-blank` | 1 | пустая строка перед футером |

Правила заданы пакетом `@commitlint/config-conventional`, локальных
дополнений в `commitlint.config.cjs` нет.

## Как это работает

Хук устанавливается автоматически при `npm install` в `vite-project/` —
скрипт `scripts/install-git-hooks.mjs` находит корень репозитория и пишет
`.git/hooks/commit-msg` с правами на исполнение. Сам файл хука в git
не отслеживается и каждый раз генерируется заново.

Проверить сообщения в уже сделанных коммитах, не коммитя:

```bash
cd vite-project
npm run lint:commit
```

Почему не `husky`: он требует каталог `.git` в текущей папке и не принимает `..`
в пути, поэтому из `vite-project/` не устанавливается. Корневой `package.json`
по-прежнему не создаётся — как именно образ `hexlet-check` ищет `package.json`,
не выяснено. Релизы тем не менее настроены: `release-please` работает в
манифестном режиме, где версия указана в `.release-please-manifest.json`, а
бампается `vite-project/package.json`. Корневой `package.json` для этого не нужен.

## Существующая история

Коммиты до этого соглашения ему не соответствуют. Пока они не запушены,
их можно переписать через `git commit --amend` или `git rebase -i`; после
пуша — только с `--force-with-lease`.

| Сейчас | По соглашению |
|---|---|
| `TS +REact +ESlint + Mantine` | `chore(vite-project): настроить typescript, react и mantine` |
| `Add README.md` ×2 | `docs: добавить readme` (два соседних коммита — дубль, склеиваются в один) |
| `Add Vitest smoke test` | `test(vite-project): добавить смок-тест на vitest` |
