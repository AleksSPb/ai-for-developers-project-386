# Календарь звонков

[![hexlet-check](https://github.com/AleksSPb/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/AleksSPb/ai-for-developers-project-386/actions)

Сервис записи на звонок. Гость выбирает дату и свободный слот, подтверждает
запись именем и почтой, а потом находит её в списке записей. Один календарь,
слоты по 30 минут в окне приёма.

Разработан совместно с ИИ.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Стек

**Клиент:** React 19, TypeScript, Vite, Mantine 9, React Router 8. Тесты —
Vitest и Testing Library.

**Сервер:** Java 25, Spring Boot 4.1.1, Maven, PostgreSQL, Liquibase.

## Что внутри

- [`GLOSSARY.md`](GLOSSARY.md) — словарь предметной области: Слот, День, Бронь,
  Гость, Встреча, Местное время гостя.
- [`docs/adr/`](docs/adr) — решения, которые выглядят ошибкой, если не знать
  причины: почему слоты не хранятся, почему между компонентами и клиентом нет
  порта, почему время в интерфейсе одно.
- `vite-project/` — клиент приложения. Команды разработки — из этой папки.
- `server/` — сервер на Spring Boot: локальный запуск, схема базы, сид окон
  приёма и первые три операции контракта — `GET /windows`, `POST /event-types`
  и `POST /bookings`. Подробности — в [`server/README.md`](server/README.md).
- `vite-project/src/domain/` — расписание, брони и время. Чистый TypeScript:
  ни React, ни сети, всё проверяется без браузера.
- `vite-project/main.tsp` и `vite-project/contract/openapi.yaml` — контракт API.
  Источник правды — `main.tsp`, из него собирается спецификация.
- `vite-project/src/api/` — слой обращения к серверу: адрес, сборка запроса и
  сгенерированный клиент. Клиент генерируется из спецификации и не коммитится.
  Компоненты и хуки ходят в него прямо, без порта между ними — подробности в
  [ADR-0006](docs/adr/0006-no-port-to-generated-client.md).

## Ограничение

**Переключиться на живой сервер пока не на что.** В `server/` работают три
операции из шести, поэтому половина контракта отдаёт `404`, а раздела
Владельца на сервере нет вовсе. Приложение целиком работает на рукописных
заглушках, и этого хватает, чтобы увидеть весь интерфейс без бэкенда. Что и
как переключать — в разделе «Два режима».

Раздел Владельца календаря не охраняется: ни профиля, ни прав, ни входа у него
нет, и открывает его любой, кто знает адрес. Это осознанное ограничение учебного
проекта, а не забывчивость — подробности в
[ADR-0004](docs/adr/0004-no-owner-entity.md).

## Установка

Клиент:

```bash
git clone https://github.com/AleksSPb/ai-for-developers-project-386.git
cd ai-for-developers-project-386
cd vite-project
npm install
```

Ручных шагов после клона не нужно: клиент генерируется сам при запуске
разработки, тестов и сборки.

Сервер (нужен Maven 3.9.x и Docker):

```bash
cd server
docker compose up --build
```

Поднимется база и сервер на `http://localhost:8080`, миграции выполнятся при
старте. Подробности — в [`server/README.md`](server/README.md).

## Использование

Приложение лежит в каталоге `vite-project`:

```bash
npm run dev       # http://localhost:5173
```

Адреса вида `/#/book` и `/#/bookings` работают на любой статической раздаче без
серверной настройки.

Как записаться: выбрать дату в календаре и свободный слот, нажать «Продолжить»,
ввести имя и почту, нажать «Подтвермить запись». Запись появится в разделе
«Брони» и переживёт перезагрузку страницы.

Дальше по горизонту календаря: сейчас доступно четыре дня, потому что столько
заводят заглушки. Сервер заводит четырнадцать, и когда он заработает, срок
станет больше. Сид одноразовый: когда эти четырнадцать дней истекут, календарь
станет пустым до тех пор, пока окна не заводят заново.

### Два режима: с заглушками и с сервером

Режим выбирает **адрес сервера**, а не отдельный флаг: заглушка поверх ответов
настоящего сервера была бы ложью.

**С заглушками** — режим по умолчанию и единственный рабочий сейчас. Переменная
`VITE_API_BASE_URL` не задана, приложение отвечает себе само рукописными
заглушками (`src/test/handlers.ts`, те же самые, что и в тестах). Работать
можно без сервера вообще.

```bash
npm run dev
```

**С сервером** — адрес задан, заглушки не поднимаются. Пока в сервере нет ни
одной операции, этот режим приведёт к пустым отказам, включать его не на что:

```bash
VITE_API_BASE_URL=http://localhost:8080 npm run dev
```

Адрес можно задать файлом `vite-project/.env.local`, чтобы не повторять его в
командах.

## Разработка

Клиентские команды выполняются из каталога `vite-project`:

```bash
npm run dev       # dev-сервер
npm run test      # тесты
npm run lint      # eslint
npm run build     # сборка и проверка типов
npm run contract  # пересобрать спецификацию API из main.tsp
npm run client    # пересобрать клиент из спецификации
```

Клиент генерируется из `contract/openapi.yaml` и в репозиторий не попадает: он
воспроизводится командами выше. Правьте `main.tsp`, а не сгенерированный файл.
Правка `main.tsp` считается изменением контракта: спецификацию нужно
пересобрать и закоммитить вместе с источником.

Тест `src/test/contract.test.ts` сверяет рукописные заглушки со спецификацией и
падает, если у операции не разобран хотя бы один код ответа.

Сообщения коммитов оформляются по Conventional Commits, правила и список
типов описаны в [docs/conventional-commits.md](docs/conventional-commits.md).
Формат проверяет commitlint на этапе коммита.
